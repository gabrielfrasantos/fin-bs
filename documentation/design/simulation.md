# Simulation contracts

## Summary

The simulation layer turns a model of how an underlying moves into a distribution of what a wheel
would earn on it. It states what a caller must supply before a run can start, what the layer
guarantees about every run, and what it deliberately refuses to express - chiefly a run whose
outcome cannot be reproduced, and a roll the strategy could not have paid for.

## Motivation

Two failures are worth designing against specifically.

The first is irreproducibility. A distribution that differs between two runs of the same inputs
cannot be compared with a second distribution, cannot be regression-tested, and cannot be explained
to anyone. It also hides defects: a rare path that breaks an invariant appears once and is gone.
Every source of randomness is therefore seeded, drawn from a stream this project defines rather than
one a standard library is free to change, and consumed in a fixed order.

The second is a simulation that quietly runs a strategy nobody could have executed. A projection
driven by a scripted price path is only as honest as the script, and a script produced by a machine
is far easier to make dishonest than one written out by hand: it can write an option at a strike no
exchange lists, price it at a premium nobody would pay, or close a position with cash the portfolio
does not have. The layer is arranged so that each of these is either impossible or refused.

## Definitions & notation

| Term | Meaning |
|---|---|
| Stream | a seeded sequence of random numbers; the same seed reproduces it exactly |
| Schedule | the ordered set of dates a run needs a price for |
| Path | one price per scheduled date, drawn from the price model |
| Script | the periods a projection runs over: what is written, at what strike, for what premium |
| Terms | the fixed description of how the wheel is run: cycle length, target delta, strike grid, when it is assessed |
| Outcome | what one path produced: terminal equity, growth rate, cycles, assignments, deepest drawdown |
| Distribution | the outcomes of a whole run, ordered so that a percentile can be read off |

## Derivation / Rules

### What the caller must supply

| Requirement | Why it is a requirement |
|---|---|
| A seed | a run that cannot be repeated cannot be checked |
| A positive initial price | a price process in the logarithm has no meaning at or below zero |
| A schedule of at least two strictly increasing dates, separated by a positive year fraction | a step of no length has no increment to draw |
| A cycle length of at least one day and at most a year | a cycle longer than a year could contain two annual reference dates and carry only one |
| An observation strictly inside the cycle, or none at all | an observation outside the cycle is not an observation of it |
| A target delta strictly between zero and one | at one, every strike qualifies and the target selects nothing; at zero, none does |
| A positive strike increment | strikes are listed on a grid, and a continuum of strikes is not tradable |
| A non-negative dividend yield | a negative yield admits a delta outside its own bounds |
| A positive volatility | a script priced at zero volatility writes options worth nothing and rolls that never trigger |
| An annual reference date that exists in every year | a rule that skips leap years is a rule nobody stated |
| A projection that has not yet been run | a run that starts from a used projection is not a run of the strategy described |
| At least one path | a distribution over nothing has no percentile |

Each of these is a precondition, checked where it is stated and stopping the run when broken.

### What the layer guarantees

- **The same seed produces the same distribution, exactly.** Not to within a tolerance: the same
  terminal equity in minor units, path by path. The normal variates are generated by a transform
  this project owns, because the mapping from a uniform stream to normal variates is not fixed by
  the C++ standard and is free to differ between implementations and versions.
- **A path is priced on exactly the dates it was asked for, and on no others.** The strategy states
  the dates it will read - each cycle boundary, each roll observation, each tax reference date - and
  the path carries a price for each of them. Nothing is interpolated, and nothing is invented for a
  date the strategy did not ask about.
- **The increment over each step is drawn from the process itself.** The log price moves by the
  integrated drift plus a normal draw scaled to the length of the step, which is the exact law of the
  process over that interval, not an approximation to it that improves with smaller steps.
- **A strike is one the market would list.** Strikes are whole multiples of a stated increment, and
  the one chosen is the nearest whose delta does not exceed the target. The rule is conservative in
  one direction on purpose: it never writes an option with more delta than was asked for, so the
  risk taken is never quietly larger than the risk configured.
- **The premium is what the model says the option is worth.** It is the valuation of the option the
  script writes, at the price the path reached on the day it is written - never a figure chosen to
  make the projection work.
- **The wheel decides what it writes; the script only says on what terms.** Whether the next option
  is a put or a call follows from where the wheel is, which follows from what the path did. The
  script is asked for one cycle at a time, after the previous one has settled, so it cannot assume a
  sequence of legs the strategy would not have taken.
- **A roll the portfolio could not fund is never offered.** Only the cash-secured leg is observed for
  a roll. Closing a short put releases collateral of the strike, and a put is never worth more than
  its strike, so the release always covers the repurchase. A covered call is collateralised in
  shares, and closing it needs cash the position can only raise by selling those shares - which is
  not a move the strategy layer makes.
- **A percentile is an outcome that occurred.** It is the outcome at a rank, so the growth rate, the
  drawdown and the assignment count reported at a percentile all belong to one path.

### What cannot be expressed

- **A run without a seed.** There is no way to ask for randomness the caller did not supply a seed
  for.
- **A strike off the grid.** A strike is a multiple of the increment; there is no argument by which
  an arbitrary strike can be handed in.
- **A premium unrelated to the option written.** The script does not accept a premium; it produces
  one.
- **A risk-driven roll of a covered call.** No observation is attached to a covered call, so the
  triggers have nothing to fire on. The limitation is deliberate and visible rather than latent: the
  alternative is a run that stops partway through, on some paths and not others, for a reason that
  looks like a defect.

## Edge cases & pitfalls

- A reference date falling on the day a projection opens is not struck. It belongs to the period
  that contains it, and containment excludes the opening day so that no two consecutive periods claim
  the same date.
- The horizon of a run is the span from its opening date to its last expiry, not the sum of its
  cycles measured in years; the two differ because a year is not a whole number of cycles.
- A wheel whose free cash is entirely committed can reach a charge it cannot pay, and the run stops.
  The cash buffer is the lever, and a buffer of a few percent of capital covers an annual wealth
  charge on the same capital with room to spare.
- Percentiles of a small run are coarse. With $N$ paths there are only $N$ distinct answers, and the
  5th and 50th percentile of twenty paths are frequently the same one.

## Alternatives considered

- **Handing the strategy the whole script up front.** Rejected: the leg written in a cycle depends on
  whether the previous one was assigned, so a script written in advance would have to predict the
  strategy's own decisions, and any disagreement between the prediction and the run would be silent.
- **Choosing strikes from a quoted options chain.** Deferred rather than rejected. A chain gives real
  strikes and real premiums, which is strictly better, but it exists only for dates that have already
  happened; a simulated future has no chain, so the strikes and premiums have to come from the model.
- **A separate ordering per reported quantity.** Rejected: ordering the growth rates separately from
  the terminal balances would let the median growth rate belong to a different path from the median
  balance, and the two reported side by side would describe no single outcome.
- **Letting a covered call be rolled by selling shares to fund the repurchase.** Rejected for now: it
  is a different strategy, not a detail of this one, and it would need a rule for how many shares to
  sell that nothing in the current model supplies.
