# Audit phase 4: `source/io`

*Date: 2026-10-19. Scope: the price-history loader, the scenario loader and writer, the broker and
tax configuration readers and the report writer in `source/io`, their tests, the shipped
configuration and data files, and the JSON library they are built on. Report only.*

## Summary

The boundary does what decisions D20, D47 and D48 ask of it. Closes are rounded on their written
digits, never through a binary number, and that rounding agrees with decimal half-to-even on
300 000 random price strings including 65 000 exact ties. Every scenario field is a whole number
with an explicit range, a saved scenario reloads field for field, strings are escaped on the way
out and unescaped on the way in, and a malformed value is reported by key name rather than
aborting. All 61 tests pass.

Two Medium findings. Omitting the `assessment` block, or misspelling its key, loads a scenario
that runs with no wealth tax and no message; a half-present block is refused correctly, which the
experiment confirmed against this report's own draft expectation (IO-1). The scenario writer
formats into a fixed buffer under a no-fail policy, so a description longer than about 1 500
characters for a three-underlying scenario, or about 800 for one, saves as a truncated file that
cannot be reopened (IO-2). The loader's minimum of two closes is one below what the first consumer
needs; that abort is ESTIM-2, and the io-side fix is noted as IO-3 without counting it again.

### IO-1 — Omitting or misspelling the `assessment` block silently means an untaxed run (Medium)

**Evidence.** `AssessmentIn` (`ScenarioLoader.cpp:124-137`) reads `assessment` through the
optional-object navigator. When the block is present, its `month` and `day` go through the
non-optional navigator inside it, so a block missing either key is refused by name: experiments
E1 and E2 produced "Integer month not found" and "Integer day not found". (The draft of this
report expected the opposite from reading the code; the experiment corrected it, and the `*day`
dereference on line 133 is therefore unreachable.) When the block is absent, or its key is
misspelled (`"assesment"`), the navigator returns nothing, `AssessmentIn` returns `nullopt`, and
the scenario loads as a run with no wealth-tax assessment. The test
`writes_a_scenario_that_keeps_no_assessment` establishes that this is intended; `design/io.md`
lists "the reference date of the wealth tax" among the fields a scenario states and does not say
it is optional, and the loader does not refuse unknown keys, so the misspelling is invisible.

**Impact.** A one-key typo, or a hand-edited file that lost the block, runs with no Box 3 charge
and no message. At the 2025 parameters the charge is 36% of 5.88% of wealth above the allowance,
about 2.1% of the portfolio a year, the largest single cost in a Dutch projection. The ledger
would show no tax row, which a careful reader can notice; nothing else says so. This is a
dangerous default rather than a misread value, hence Medium.

**Proposed fix.** Make the choice explicit: either require the block and provide an explicit
opt-out (`"assessment": null`, or `"wealth_tax": "none"`) that the result also reports, or keep
it optional and have the run state "no wealth tax assessed" in its output. Refusing unknown
top-level keys would catch the misspelling as well. **Suggested tests.** A scenario without the
block loads only with the explicit opt-out; a misspelled block key is refused.

### IO-2 — `Formatted` truncates a long scenario silently (Medium)

**Evidence.** `Formatted` (`ScenarioLoader.cpp:257-307`) writes into a `std::vector<char>` of
`1024 + 512 × underlyings` bytes through an `infra::StringOutputStream` constructed with
`infra::noFail` (line 261), which discards output that does not fit without reporting it. The
`scenario` name is free text with no length check on read (`TextAt`, line 114–122) or in the
presentation layer. Measured: the example scenario formats to about 1 020 bytes plus the name.
With three underlyings the longest name that round-trips is 1 525 characters; at 1 550 the
document is exactly 2 560 bytes, the buffer size, and reloading it fails with
"JsonFileReader: Invalid JSON object". With one underlying the limit is 825 characters against a
1 536-byte buffer. The truncation itself produces no error.

**Impact.** A person who writes a long description, a few paragraphs for a three-underlying
scenario or one for a single underlying, and saves gets a file that ends mid-document; the save
appears to succeed and the file cannot be reopened. No number is wrong; a scenario is lost. The
configuration paths are short relative names today (`present/ScenarioDocument.cpp:69-70`), which
keeps the margin, but nothing enforces that, and the unit of the limit is bytes, so a description
in a language with multi-byte characters reaches it sooner.

**Proposed fix.** Size the buffer from the content (the library offers `JsonEscapedStringSize`),
or write to a growable string, or construct the stream without `noFail` and report a failed
write by name. **Suggested test.** A scenario with a 2 000-character name round-trips.

### IO-3 — Two closes accepted, three needed (Medium; counted as ESTIM-2)

`PriceCsvLoader.cpp:167-168` refuses fewer than two closes; `HistoricalVolatility::From` needs
two returns. The io-side fix is to require three closes here and in `PriceSeries::From`, with the
message updated; see ESTIM-2 for the demonstration and the alternative.

### IO-4 — Amounts are bounded by `int32_t`, and the message misnames the cause (Low)

**Evidence.** Every integer field is read through `JsonIntegerNavigatorToken`, which returns
`int32_t` (`JsonObjectNavigator.hpp:109`). The library keeps a larger integer as a
`JsonBiggerInt` and `GetOptionalValue<int32_t>` then returns nothing (`Json.cpp:634-643`), so the
navigator throws "Integer `key` not found" (`JsonObjectNavigator.cpp:69`). The same wording is
produced for a decimal (`0.75`) and for a string. D20 records that missing and mistyped keys share
a message; a value that is present and too large is a third case nobody documented, and the
ceiling of 2 147 483 647 cents (21 474 836.47 in euro or dollars) on `capital_cents` and every
other amount appears nowhere. Experiment E3 outcome: refused with exactly that message.

**Impact.** A capital above 21.47 million cannot be stated, and the reason given is wrong. Safe,
since nothing is misread, but a real limit for a real-money tool.

**Proposed fix.** Read amounts with the library's `GetIntegerAs<int64_t>`, which handles
`JsonBiggerInt`, and keep the `int32_t` readers for counts and basis points; or document the
bound in `design/io.md`. Wrap the navigator call so that "present but not a whole number in
range" is reported as such. **Suggested tests.** `capital_cents: 3000000000` either loads or is
refused with a message that says why.

### IO-5 — Common export forms are refused with a confusing message (Low)

**Evidence.** The header must equal `date,close` byte for byte (`PriceCsvLoader.cpp:13, 121`). A
UTF-8 byte-order mark, which spreadsheet exports often prepend, makes the message "Columns are
named ﻿date,close rather than date,close", with the invisible mark the only difference. A space
after the comma (`2025-01-02, 95.00`) is refused as "Close  95.00 is not an amount". A semicolon
separator with a decimal comma (the Dutch Excel default) is refused as a row that does not hold
a date and a close. Experiment E5 outcome: all four forms refused with the messages quoted above.

**Impact.** Usability only; nothing is misread.

**Proposed fix.** Strip a leading byte-order mark; trim spaces around fields; optionally accept
`date;close` with a decimal comma when the header says so. Keep refusing everything else.

### IO-6 — Tickers are written unquoted into the CSV (Low)

**Evidence.** The scenario loader accepts any non-empty, unique ticker (`ScenarioLoader.cpp:152`);
`CycleReport` concatenates it with commas (`ReportWriter.cpp:75`). A ticker containing `,`, `"`
or a newline produces a row with the wrong number of fields. `TextOf(Money)` also negates
`INT64_MIN` (`ReportWriter.cpp:23`), which is unreachable.

**Proposed fix.** Refuse those characters in a ticker at the scenario boundary (by name), which
is cheaper and clearer than CSV quoting. **Suggested test.** A ticker `"A,B"` refused.

### IO-7 — Roll and observation day counts are not related to the cycle length (Low)

**Evidence.** `roll_days_to_expiry` is bounded to 0–365 and `observation_days_before_expiry` to
0–365 and below `days_per_cycle` (`ScenarioLoader.cpp:177-191`), but `roll_days_to_expiry` may
exceed `days_per_cycle`, in which case the time trigger fires on the day a cycle opens.
`strategy::IsWellFormed(RollTriggers)` checks ranges only.

**Impact.** Depends on how the strategy treats a roll on day one; assessed in phase 7. The
boundary could refuse it now, naming the field.

### IO-8 — Three copies of the same readers (Low)

`CurrencyNamed`, `AmountAt` and `BasisPointsAt` exist in `TaxConfig.cpp`, `BrokerConfig.cpp` and
`ScenarioLoader.cpp` with small differences (the scenario's `AmountAt` takes a lower bound, the
others refuse negatives only). COSTS-5 is an example of two such paths drifting. One shared
reader would make the boundary's rules one thing to review.

### IO-9 — `IsWellFormed(Scenario)` is largely redundant (Info)

`ScenarioLoader.cpp:234-250` re-checks emptiness, positivity and currency agreement that the
field readers already enforced. Harmless; worth a comment saying which checks are only reachable
by constructing a `Scenario` in code.
